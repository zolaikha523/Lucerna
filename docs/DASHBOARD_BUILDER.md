# Dashboards: one-click generator, viewer and Studio

## The one-click flow
**Dashboard Studio › Generate**

1. **Data.** Upload a file (Excel, CSV, JSON, or a table inside Word or PDF), or pick a dataset you have already uploaded.
2. **Theme.** Choose Corporate Light, Executive Dark, Modern Vibrant or Research & Minimal. You can also open
   **Branding** to set a title and subtitle, show the organisation name, and choose a logo: the organisation logo,
   a custom PNG or JPEG under 1 MB, or no logo.
3. **Generate Professional Dashboard.** Lucerna analyses the data and opens the finished dashboard in the viewer.

You do not need to map variables first. When nothing has been confirmed yet, the dashboard says so in its
methodology, and counts are labelled "records" rather than "households" or "respondents".

## How the engine decides (no dataset-specific rules)
The engine is `lucerna/quant/engine.py`. It works from the structure and content of the data, not from fixed
layouts, fixed KPIs or particular column names. Tests check that its source contains no sheet or column names from
any test dataset.

| Step | What happens | Where |
|---|---|---|
| Workbook reading | Each sheet is classified as survey/record data, monitoring counts, sampling frame, codebook, documentation, indicator map, lookup or other table. Classification uses structure and content: size, column types, dictionary-like columns, documentation text, and values that name other sheets' columns. The largest analytical sheet becomes the main dataset. Related sheets are linked by value overlap (at least 60%), not by name alone. | `quant/workbook.py` |
| Codebooks | Codebook sheets are never analysed as data. Their labels are applied to the main sheet's variables (filtered by a "sheet" column when there is one). | `quant/store.py` |
| Variable roles | Dates, location hierarchy (province → district → camp/site → block), origin/destination, sex, age, household size, weights, rounds, identifiers, personal data (excluded), yes/no items, categories, rating scales (Likert), multiple-response, measures, free text. | `quant/profile.py`, `Vars` in `engine.py` |
| Domain | Scored from the data's own words (column names, labels, values, sheet names). WASH, food security, cash/MPCA, PDM, protection, displacement, health, education, livelihoods, shelter, markets, programme monitoring, needs assessment, research survey, emergency. When the evidence is weak it says **General dataset** rather than guessing. | `quant/domain.py` |
| Comparison group | The best-populated population characteristic with 2–7 groups (type, group, programme, sex, round). Outcome variables are penalised so that, for example, "latrine type" is not used to split a WASH dashboard. | `_segment` in `engine.py` |
| Pages | Only pages the data supports: Executive Overview; Who Is Represented; Mobility & Flows; one page per theme found (split when more than 8 charts); Ratings & Perceptions (3 or more items on the same scale); Additional Findings; Change Over Time; Geographic Analysis; Group Comparisons (significance tests); Relationships Between Measures; Related Data (one per linked sheet); Data Quality & Methodology. Pages without enough content are merged or dropped, so no page is empty. | `build` in `engine.py` |
| Safeguards | Fewer than 30 records: descriptive pages only. No dates: no trend pages. Fewer than 3 periods: no trends. Fewer than 12 months: no forecast. Same number of records on every collection date (fixed panels): no volume-over-time charts. A partly covered first or last week/month is left out of trend comparisons. A missing-values chart appears only when values are missing. | `engine.py`, `explain.py` |

## Insights under every visual
Each chart has an **Insights, method & limitations** panel with eight parts: what the visual shows, key findings,
why it matters, interpretation, implications, suggested follow-up (for analyst review), limitations, and source and
methodology (sheet, variables, formula, denominator, filters, exclusions, n, method). The text is generated by rules
from the computed numbers (`quant/explain.py`); every number in it comes from the same calculation as the chart.
Significance tests: chi-square for proportions, Kruskal–Wallis or Mann–Whitney for measures, and Spearman for trends
and associations. p-values are written as "p < 0.001" or "p = 0.034". Small differences (under 10 percentage points)
are described as small, with no action suggested.

**Reword with local AI** (optional) asks the local Ollama model to rephrase the text. Any number that is not
already in the verified facts is removed, and the result is labelled as an AI draft.

## The viewer (separate from the builder)
- Full-screen page with no builder controls: the header (logo, organisation, title, source, period, version), page
  tabs, filters, KPI cards, charts, insights, and a **Key findings** panel on the overview.
- **Filters** (location, comparison group, sex, round, date range) apply to every visual. Clicking a bar or slice
  cross-filters the page, and **Clear** removes all filters.
- **Drill-down.** Location charts go down one level per click (province → district → site); **Drill up** goes back.
- **Theme.** Editors save a new theme. Viewers can preview one without changing the saved dashboard.
- **Export.** PDF (landscape, cover page, every page with its charts, findings and limitations), Excel (an About
  sheet, one sheet per table, KPIs, insights), and a detailed Word report. Exports use the filters currently
  applied and are recorded in the audit log.
- **Present** shows one page at a time full-screen, with Previous and Next buttons.
- Each chart can also be downloaded as CSV data or as a PNG image.

## My dashboards
Open, refresh from the current data (this creates a new version), rename, duplicate (theme and branding are kept),
restore an earlier version, or delete (confirmation required). A **stale** tag appears when the underlying dataset
has changed since the dashboard was generated.

## Custom editor
**Dashboard Studio › Custom editor** is the manual builder. It covers the same set of visual types (23) plus the
generator's multi-line, comparison table and methodology types. It uses a 12-column grid with reordering and width
controls, and has templates and version history. There is no free drag-and-drop canvas, because Streamlit does not
provide one.

## Colour and accessibility
Each theme's categorical palette was checked with a colour-vision-deficiency validator against that theme's own
surface colour. Categories keep the same colour when filters change. Every chart uses one y-axis, and the base n is
shown under each chart.
